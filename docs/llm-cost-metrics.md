# LLM コスト計測の定義

会話・メッセージ当たりの原価を KPI として管理するための計測単位と、記録の範囲を定義する。

## 計測単位

| 単位 | 定義 | データ上の対応 |
| ---- | ---- | -------------- |
| メッセージ | ユーザー発話 1 回とそれに対する応答 1 回の 1 往復 | `llm_usage` の `source = 'chat'` 1 行 |
| 会話 | 1 つのスレッド | `llm_usage.thread_id`（= `mastra_threads.id`） |
| セッション | 独立した単位としては定義しない | 会話の粒度がチャネルごとに異なるため下表を参照 |

**原価 KPI の主指標は「メッセージ当たり原価」とする。** 会話（スレッド）の寿命がチャネルごとに異なるため、チャネル横断で比較できるのはメッセージ単位だけ。

### チャネルごとの「会話」の粒度

| チャネル | スレッドの寿命 | 注意 |
| -------- | -------------- | ---- |
| Web / ウィジェット | ブラウザセッションごと | いわゆる「1 会話」に最も近い |
| LINE | ユーザーごとに 1 スレッド（生涯） | 会話単価は「期間内の合計」であり 1 会話の単価ではない |
| 電話 | 通話ごとに 1 スレッド | 1 通話 = 1 会話 |

## 記録の仕組み

- LLM 呼び出し 1 回ごとに `llm_usage` へ 1 行記録する（モデル・入出力/推論/キャッシュトークン・チャネル・用途・エージェント名・スレッド ID）。エージェント名により会話ごとの内訳（本体 / ナレッジ検索 / Web 検索等）が分かる
- `cost_usd` は**記録時点の単価**で計算して永続化する。単価テーブル（`server/src/lib/llm-pricing.ts`）を更新しても過去実績は書き換わらない。`cost_usd` が NULL の旧行だけ集計時に現行単価で概算する
- キャッシュ読み取りトークンは割引単価で計算する（gpt-5.6 系: 入力単価の 10%、gpt-4.1-nano・Gemini: 25%）
- 会話時間は集計期間内の `mastra_messages` の最初と最後のメッセージ時刻から導出する（コストと同じ期間で揃える）
- メインエージェント以外（委譲サブエージェント・intent 分類・ペルソナ抽出）は各エージェントの `defaultOptions.onFinish` で記録し、`source` 列で区別する

### 費用の区分

運用コスト全体と 1 会話あたりの原価は別の指標として扱う。

| 区分 | 含む source | 1 会話あたりの原価に含む |
| ---- | ----------- | ------------------------ |
| 会話 | chat / subagent / intent-classify / rerank、およびスレッドに紐づく embedding（検索クエリのベクトル化） | ○ |
| ナレッジ同期 | スレッドに紐づかない embedding（ナレッジ登録時のベクトル化） | ✗ |
| 定期処理 | persona-extract / weekly-report / image-convert | ✗ |

### source の区分

| source | 内容 | スレッド紐づけ |
| ------ | ---- | -------------- |
| `chat` | メインエージェントの応答（= 1 メッセージ） | あり |
| `subagent` | 委譲サブエージェント（knowledge / web 検索 / 音声要約等） | あり |
| `intent-classify` | casual / thinking 分類 | あり |
| `persona-extract` | ペルソナ抽出バッチ | あり |
| `weekly-report` | 週次レポート生成 | なし |
| `image-convert` | 画像・PDF の Markdown 変換（ナレッジ・配信） | なし |
| `rerank` | ナレッジ検索結果のリランク（1 検索で最大 10 回） | あり |
| `embedding` | 埋め込み（検索クエリはスレッドあり、ナレッジ同期はなし） | 両方 |

## 原価に含まれないもの

以下は `llm_usage` に記録されない。メッセージ原価を予算（目安 7〜8 円/メッセージ）と比較する際は別枠として扱う。

- Google Custom Search API
- Twilio の通話料・インフラ費（Cloudflare）
- eval スクリプトの実行分（ローカル集計のみ）

計測の既知の限界:

- 中断された音声ターン（割り込み・切断）はプロバイダが usage を返さないため記録されない
- フォールバック発火ターンは最終応答モデルの単価で全ステップ分を計算する（ステップ別のモデル按分はしない）

## 保持期間と長期 KPI

`llm_usage` の raw 行は 180 日で削除される。長期のトレンドは `weekly_reports.stats`（会話数・メッセージ数・モデル別 usage とコスト）で恒久保存される。

## 確認方法

管理画面ダッシュボードの「利用コスト」タブ（super_admin 限定）。

- **コスト**: 1 メッセージ平均（予算 8 円との対比つき）・30 日合計・会話数・日別推移。エージェント別の内訳を積み上げバーで表示し、会話一覧は行クリックでメッセージ（1 往復）ごとのコスト・エージェント内訳・応答時間が開く
- **週×モデル別**: トークン量とコストの推移

円表示は 1USD=150 円換算の目安で、請求は USD で確定する。用途別（会話 / ナレッジ同期 / 定期処理）とプロバイダ別の内訳は `GET /admin/analytics/usage/operation` が返す。円表示は 1USD=150 円換算の目安で、請求は USD で確定する。
