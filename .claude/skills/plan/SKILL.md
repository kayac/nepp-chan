# 実装計画の作成

## 手順

### 1. 情報収集

引数からタスクの内容を把握する:
- テキスト → 作業概要として扱う
- `#123` → `gh pr view 123` または `gh issue view 123` で詳細を取得

関連するコードを読み、影響範囲を把握する。

### 2. Plan ファイルの作成

`.brain/plans/{yyyyMMdd}-{slug}.md` に以下のテンプレートで作成する:

```markdown
# {タスクタイトル}

Branch: {ブランチ名}
Created: {yyyy-MM-dd}

## 背景

{なぜこの変更が必要か。1-3 文で}

## 要件チェックリスト

- [ ] REQ-1: {要件 1}
- [ ] REQ-2: {要件 2}
- [ ] REQ-3: {要件 3}

## 設計方針

{どう実装するか。変更するファイル・モジュールと方針}

### 変更対象

| ファイル / モジュール | 変更内容 |
|---|---|
| {path} | {概要} |

### 選択しなかった代替案

{検討して却下した方針があれば}

## テストケース

- [ ] TC-1: {テストケース 1}
- [ ] TC-2: {テストケース 2}

## 完了条件

- [ ] 全 REQ がチェック済み
- [ ] 全 TC がパス
- [ ] lint / format / build が通る
- [ ] レビュー完了
```

### 3. ユーザーに確認

Plan ファイルの内容をユーザーに提示し、承認を求める。
修正指示があれば反映する。

## 注意

- 実装中に要件が変わったら Plan ファイルも更新する（stop-check が未完了 REQ を検出して通知する）
- 軽微な修正やリファクタでは Plan 不要（CLAUDE.md の計画ファーストセクション参照）
